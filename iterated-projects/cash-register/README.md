## This is one of the latest and most difficult projects I have done with JavaScript

This is a Cash Register, whereby the amount of money in the register can be changed, as well as the "price" of an item and the cash the user has. It then calculates the change due after purchasing one unit of an item, until the cash register no longer has the funds to give back exact change.

## Why did I decide to do this?

I decided to do this because, similarly to the "numeral-roman-converter", I could not instantly think of a way to approach it, and so I thought it would make for a nice challenge. After some thinking, I came up with a solution which involved recursion. I initially thought recursion was a clever way of dealing with this project because it seemed as if the problem of giving change could be broken down into smaller, self-similar problems. However, the recursion call ended up getting me in some trouble when it came to handling the stack (probably also in part due to poor code cleanliness and over-complicated logic which I wanted to trim down anyway), which I thought an iterative approach may circumvent.

Each README.md file goes into slightly more depth, but whereas I wanted to apply what I had learnt in the "numeral-roman-converter" about using recursion as needed, I actually realised that for this project an iterative approach may be easier to work with and read (although I still believe a cleaner recursive approach is totally valid).
